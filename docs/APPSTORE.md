# App Store 申請の手引き（ゆめテープ / YUMETAPE）

ウェブ版をiPhoneアプリとして包み、App Storeに出すための手順です。上から順にやれば進みます。

> **注意**：Appleの画面・必要書類・価格・スクリーンショットの規定は変わります。この文書と違う画面が出たら、**Appleの画面の指示を優先**してください。

---

## 0. 全体像とかかるもの

| | 内容 |
|---|---|
| **費用** | Apple Developer Program 年会費 **US$99／年**（日本円で1万5千円前後。為替で変動） |
| **必要な機材** | Mac（Xcodeを入れる）、iPhone実機（動作確認とスクリーンショット用） |
| **かかる期間** | 登録の本人確認に数日、審査は1〜2日程度。初回は合計1〜2週間みておくと安心 |
| **更新** | 年会費を払い続ける限り公開が続きます。止めるとアプリはストアから消えます |

進め方の順番。**いきなり公開審査に出さず、TestFlightで自分の実機に入れて確かめてから**にしてください。

```
① Developer Program に登録（お金がかかるのはここだけ）
② Macに Xcode を入れる
③ アプリの器をビルドして、自分のiPhoneで動かす   ← ここが山場
④ TestFlight に上げて、アプリとして使い込む
⑤ ストアの情報（説明文・スクショ）を埋める
⑥ 審査に出す
```

---

## 1. Apple Developer Program に登録する

1. iPhoneで **Apple Developer** アプリを入れるか、https://developer.apple.com/programs/ を開く
2. ふだん使っているApple IDでサインイン（**2ファクタ認証が有効になっている必要があります**）
3. 個人（Individual）か組織（Organization）かを選ぶ → **ここが分かれ道です。下の「本名の話」を読んでから選んでください**
4. 氏名・住所を入力して支払い

### 本名の話（先に決めてください）

**個人（Individual）で登録すると、App Storeの「販売元」に戸籍上の氏名がそのまま表示されます。** ペンネームで活動している場合、ここで本名が公開されます。

避けたい場合は次のどちらかです。

- **個人事業主として登録する**（屋号で出せます）。開業届を出し、**D-U-N-S番号**という事業者識別番号を取得します。D-U-N-S番号は無料ですが、申請から取得まで**数日〜2週間**ほどかかります
- **法人として登録する**（法人設立が必要）

どちらも「組織（Organization）」枠での登録になります。**あとから個人→組織への変更は手間がかかる**ので、最初に決めるのが得策です。

---

## 2. Macの準備

1. App Store から **Xcode** を入れる（無料。サイズが大きいので時間がかかります）
2. Xcode を一度起動して、追加コンポーネントのインストールを済ませる
3. ターミナルで Node.js が入っているか確認

   ```bash
   node -v
   ```

   入っていなければ https://nodejs.org/ からLTS版を入れてください。

---

## 3. アプリの器を作る

このリポジトリをMacに持ってきて、ターミナルで作業します。

```bash
git clone https://github.com/maigohasegawa/yumetape.git
cd yumetape

# Capacitor（ウェブアプリをiOSアプリに包む仕組み）を入れる
npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/share @capacitor/filesystem

# アプリに入れるファイルをまとめる
npm run build

# iOSプロジェクトを作る（初回だけ）
npx cap add ios

# 変更を反映してXcodeを開く
npm run ios
```

`capacitor.config.json` はこのリポジトリに入れてあります。アプリの識別子は `io.github.maigohasegawa.yumetape` にしてあります。変えたい場合はこのファイルを編集してから `npx cap add ios` を実行してください（**あとから変えると作り直しになります**）。

### Xcodeでやる設定

**① カメラ・マイク・写真の説明文を入れる（必須）**

これが無いとアプリが落ちますし、審査でも必ず落ちます。Xcodeの左側から `App > App > Info.plist` を開き、以下を追加します（右クリック → Open As → Source Code で貼り付けるのが早いです）。

```xml
<key>NSCameraUsageDescription</key>
<string>撮影のためにカメラを使います。映像は端末の中だけで処理され、どこにも送信されません。</string>
<key>NSMicrophoneUsageDescription</key>
<string>録画に音声を入れるためにマイクを使います。設定でオフにできます。</string>
<key>NSPhotoLibraryAddUsageDescription</key>
<string>撮影した写真・動画を写真アプリに保存するために使います。</string>
```

**② iPhone専用にする**

`App` を選んで **General → Supported Destinations** から **iPad を外します**。iPadを残すとiPad用のスクリーンショットも必要になり、動作確認の手間が倍になります。

**③ 画面の向き**

General → Deployment Info で、Portrait（縦）に加えて横向きも許可しておくと、横位置の撮影がしやすくなります。お好みで。

**④ アプリアイコン**

`store/icon-1024.png` を、Xcodeの `Assets.xcassets > AppIcon` にドラッグします。

**⑤ 署名**

Signing & Capabilities で Team に自分のアカウントを選び、**Automatically manage signing** にチェック。

### 実機で動かす

iPhoneをMacにつなぎ、Xcodeの上部で実行先に自分のiPhoneを選んで ▶ を押します。

> **カメラが映らないときの最初の確認点**：`capacitor.config.json` の `"iosScheme": "https"` が効いているか。カメラは安全な接続からしか使えず、この設定が無いとアプリ内でカメラが取れません。設定を変えたら `npm run ios` をやり直してください。

## 4. TestFlight で使い込む

Xcode の Product → Archive → Distribute App → **TestFlight** に上げると、審査なしで自分のiPhoneに配れます（App Store Connectでの簡単な設定が要ります）。

ここで**普段の生活で何日か使ってみてください**。ウェブ版と挙動が違うところ（保存、一時停止、速度変換など）が出たら教えてください。直します。

---

## 5. ストアの情報を用意する

App Store Connect（https://appstoreconnect.apple.com/）で新しいAppを作り、以下を埋めます。**文章は `store/listing.md` にすべて用意してあるので、コピーして貼るだけです。**

| 項目 | 用意済みか |
|---|---|
| App名・サブタイトル・説明文・キーワード | ✅ `store/listing.md` |
| プライバシーポリシーURL | ✅ `https://maigohasegawa.github.io/yumetape/privacy.html` |
| サポートURL | ✅ `https://github.com/maigohasegawa/yumetape` |
| アプリアイコン 1024×1024 | ✅ `store/icon-1024.png`（透明なし・角丸なしで作成済み） |
| カテゴリ | 写真／ビデオ |
| 年齢制限 | 質問に答えるだけ。該当項目なしで4+になるはず |
| **スクリーンショット** | ⬜ **実機で撮ってください**（下記） |

### スクリーンショット

**6.9インチのiPhone用が必須です**（1290×2796 または 1320×2868。規定は変わるので申請画面の表示に従ってください）。iPhone 17 Pro Maxクラスの実機で撮ればそのサイズになります。

3〜5枚あれば十分です。おすすめの構成：

1. `VHS 1984` で撮った日常の風景（何のアプリか一目で分かるもの）
2. `DREAMCORE` か `ゆめかわ`（色の違いが出るもの）
3. `心霊ビデオ` か `呪いのテープ`（振れ幅を見せる）
4. プリセット一覧が写っている画面
5. 設定画面（調整できることが伝わる）

撮り方は、実機で **電源ボタン＋音量上ボタン** の同時押しです。撮ったものを送ってもらえれば、**文字入れや枠のデザインはこちらで整えます。**

### プライバシー情報（App Privacy）

「データを収集していますか？」→ **収集していません（No）** で通ります。このアプリは通信を一切しません。

### 輸出コンプライアンス

「暗号化を使用していますか？」と聞かれます。アプリ版はネットワーク通信をしないため、通常は「いいえ」で問題ありません。**質問文をよく読んでご自身で判断してください**（虚偽申告は問題になります）。

## 6. 審査に出す前に — 落ちやすいポイント

### いちばんの関門：4.2 Minimum Functionality

**中身がウェブサイトそのままのアプリは弾かれます。** ゆめテープは実際にはリアルタイム映像処理アプリなので中身は十分ですが、「ウェブを包んだだけ」に見えないことが大事です。すでに次の対策を入れてあります。

- ブラウザのバーやアドレス欄が出ない（ネイティブの画面として起動）
- カメラ・マイクの許可がiOS本来のダイアログで出る
- 保存がiOSの共有シート（ネイティブ）経由
- 「ホーム画面に追加してください」といったウェブ向けの案内をアプリ版では非表示
- 通信なしで完全に動作する

**審査メモ（App Review Information の Notes）に、次のように書いておくと通りやすくなります。**

```
このアプリは、カメラ映像をGPUシェーダーでリアルタイムに加工し、
エフェクトを焼き込んだ状態で写真・動画を記録するカメラアプリです。
ネットワーク通信は行わず、すべての処理は端末内で完結します。

主な機能：
・15種類のプリセット（VHS / ホラー / ドリーム / グリッチ）
・30以上のパラメータを個別に調整し、名前をつけて保存
・録画の一時停止（1本の動画内で場面を切り替える）
・0.25倍〜4倍の速度での録画
```

### そのほか

- **App名が既に使われている場合があります。** 「ゆめテープ」が取れなかったときの候補も `store/listing.md` に書いてあります
- **説明文にAndroidや他社ストアの名前を書かない**（弾かれます）
- **「ベータ」「テスト版」といった表現を入れない**
- 権限の説明文は、**なぜ必要かが具体的に**書かれている必要があります（上の文面はその要件を満たしています）

---

## 7. 出したあと

- 審査は通常1〜2日。落ちても理由が返ってくるので、直して出し直せます（回数制限なし）
- 落ちた理由を送ってもらえれば、**こちらで直します**
- ウェブ版を更新したら、`npm run build && npx cap sync ios` でアプリ版にも反映できます。ストアに出すには再度Archiveと審査が必要です

---

## 私（Claude）ができること・できないこと

| できる | できない |
|---|---|
| コードの修正・機能追加 | Developer Programへの登録と支払い |
| プライバシーポリシー、説明文、キーワード | Xcodeでのビルド・署名・アップロード |
| アイコン、スクリーンショットの加工 | 実機での撮影と動作確認 |
| リジェクト理由への対応 | 審査ボタンを押すこと |
