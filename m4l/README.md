# GRAIN IMAGE — 画像・映像をグラニュラーサウンドにする M4L デバイス

Ableton Live 用の Max for Live インストゥルメントです。画像や動画を読み込み、その **ピクセルそのものを波形として** 鳴らします。

- `GrainImage.amxd` — Live に入れるデバイス本体
- `GrainImage.maxpat` — 同じ内容の Max パッチ（後述のフォールバック用）
- `build_device.py` — 上の2つを生成するスクリプト
- `maxpat.py` / `amxd.py` — パッチ JSON と `.amxd` バイナリのビルダー
- `validate.py` — 生成物の構造チェック

必要なもの: **Ableton Live Suite**、または Live + Max for Live。Max 8 以降を想定しています。外部オブジェクト（サードパーティ製 external）は一切使っていません。

---

## 何をしているのか

よくある「画像を音にする」ツールは、画像をスペクトログラムとみなして逆FFTします。このデバイスは違うやり方をします。

**画像の1行 = 1つの波形（ウェーブテーブル）** として扱います。

1. 読み込んだ画像／動画フレームを 256×256 に変換します
2. 赤プレーンと青プレーンを取り出し、0..255 を -1..1 の音の振幅にマッピングします
3. できあがるのは「256サンプルの波形が、縦に256本積み重なったもの」です
4. グラニュラーエンジンが、その中の1行をオーディオレートで繰り返し読みます

つまり **画像の横方向が音色、縦方向がウェーブテーブルの並び** になります。`Position` で縦位置を選ぶと音色が変わり、`Scan` で縦にゆっくり動かすと、画像を上から下へなぞりながら音色がモーフィングしていきます。

グレインは8本のストリームが位相をずらして並走します。1グレインごとに、位置のばらつき（`Spray`）、ピッチのばらつき（`Detune`）、パン（`Stereo`）、そのグレイン内での縦方向の移動量（`Sweep`）が新しく抽選されます。

**赤が左チャンネル、青が右チャンネル** です。`Color` を上げると画像の色ズレがそのままステレオの広がりになります。モノクロ画像では `Color` を上げても効果はありません（赤と青が同じ値のため）。

動画を読み込んで再生させると、波形の元になっている画像が毎フレーム書き換わるので、音がずっと動き続けます。`LIVE` を切ると、そのフレームで固まります（フリーズ）。

## インストール

1. `GrainImage.amxd` を、Live のユーザーライブラリに置きます
   - macOS: `~/Music/Ableton/User Library/Presets/Instruments/Max Instrument/`
   - Windows: `%USERPROFILE%\Documents\Ableton\User Library\Presets\Instruments\Max Instrument\`
2. Live のブラウザに出てくるので、**MIDIトラック** にドラッグします

ユーザーライブラリに入れなくても、Finder / エクスプローラから直接 MIDIトラックにドラッグしても読み込めます。

## 使い方

1. `IMAGE` ボタンで画像（jpg / png など）、`VIDEO` ボタンで動画を選びます。左下の枠にファイルをドラッグ＆ドロップしてもOKです（拡張子で自動的に振り分けます）
2. プレビューに絵が出たら、`DRONE` が入っている状態なら **もう鳴っています**
3. `Position` を回すと、画像のどこを読むかが変わります
4. MIDIノートを弾くとピッチが変わります。ノートを使わずドローンとして鳴らしたいときは `DRONE` をオンのまま、`NOTE` で基準音を決めてください

音が出ない場合は、`DRONE` がオンか、`Volume` が下がりすぎていないか、そして画像がプレビューに表示されているかを確認してください。

### 最初に触るとおもしろいところ

- `Position` をゆっくり回す（音色が画像に沿って変わる）
- `Scan` を 0.05 くらいにして放置する（画像を縦になぞり続ける）
- `Grain` を短く（10ms前後）＋ `Density` を高く（30Hz前後）でザラついたクラウドに
- `Grain` を長く（300ms超）＋ `Density` を低く（3Hz前後）でゆったりしたパッドに
- `Contrast` を上げるとコントラストの強い画像ほど歪みます

## パラメーター

すべて Live からオートメーションできます。

| 名前 | 範囲 | 初期値 | 内容 |
|---|---|---|---|
| `Position` | 0–1 | 0.5 | 画像の縦位置。どの行を波形として読むか |
| `Scan` | -2–2 Hz | 0 | 縦位置の自動スクロール速度。マイナスで逆方向 |
| `Spray` | 0–1 | 0.15 | グレインごとの縦位置のばらつき |
| `Grain` | 5–500 ms | 90 | グレインの長さ |
| `Density` | 0.5–40 Hz | 12 | 1ストリームあたりのグレイン発生頻度（実際の密度は×8） |
| `Pitch` | -24–+24 半音 | 0 | 全体のピッチ |
| `Detune` | 0–1 | 0.06 | グレインごとのピッチのばらつき |
| `Sweep` | 0–1 | 0.12 | 1グレインの中で縦位置がどれだけ動くか |
| `Color` | 0–1 | 0.6 | 赤／青の分離量＝色によるステレオ感 |
| `Stereo` | 0–1 | 0.7 | グレインごとのパンの広がり |
| `Tone` | 200–18000 Hz | 9000 | 出力ローパスフィルター |
| `Contrast` | 0.2–4 | 1.6 | 画像のコントラスト＝音の歪み量 |
| `Volume` | -70–+6 dB | -12 | 出力音量 |
| `Note` | 24–84 | 48 | MIDIを弾かないときの基準音 |
| `DRONE` | on/off | on | オンだとノートなしでも鳴り続ける |
| `LIVE` | on/off | on | 動画の更新。オフで現在のフレームにフリーズ |

## 制限と、わかっている癖

正直に書いておきます。

- **モノフォニックです。** 和音を弾いても最後のノートのピッチになります。厚みが欲しいときはトラックを複数使ってください。
- **音は意図的にザラついています。** `jit.peek~` は補間なしでピクセルを読むので、256サンプルのウェーブテーブルを高い音で鳴らすとエイリアシングが出ます。デジタルで荒い質感になりますが、これはこのデバイスの持ち味として残してあります。丸くしたいときは `Tone` を下げてください。
- **画像によって音量が大きく変わります。** 明るくコントラストの高い画像ほど大きく歪みます。`Contrast` と `Volume` で調整してください。DC成分は出力段で除去しています。
- **動画は Live のトランスポートと同期しません。** 読み込んだ時点から自分のペースでループ再生します。
- 静止画は `jit.matrix` の `importmovie`、動画は `jit.movie` で読み込んでいます。読み込めないファイル形式があった場合は、一度 jpg / png / mp4 に変換してみてください。

### テストについて

このデバイスは Max / Live が動かない環境で生成しました。**私自身が Live 上で音を鳴らして確認したわけではありません。** 検証したのは以下の範囲です。

- `.amxd` バイナリコンテナの構造（ヘッダ、チャンクサイズ、JSONのラウンドトリップ）
- パッチ JSON の構造 — 全パッチコードの参照先ボックスと inlet / outlet 番号の妥当性、サブパッチャの inlet / outlet 数の一致、Live パラメーター名の重複（`validate.py`）
- 使用オブジェクトが全て標準の Max / MSP / Jitter オブジェクトであること

信号の流れとオブジェクトの引数は設計どおりのはずですが、実機で微調整が要る可能性はあります。動かない箇所があれば `build_device.py` を直して再生成するのが早いです。

## 作り直す

```bash
python3 m4l/build_device.py   # GrainImage.maxpat と GrainImage.amxd を生成
python3 m4l/validate.py       # 構造チェック
```

Python 3.8以上のみで動きます（追加ライブラリ不要）。

`build_device.py` の先頭にある `WIDTH` / `HEIGHT` / `VOICES` を変えると、ウェーブテーブルの長さ・本数・グレインストリーム数が変わります。`VOICES` を増やすとグレインが濃くなり、CPU負荷も上がります。

### `.amxd` が開けなかった場合

`.amxd` のバイナリ形式は Ableton の公式仕様ではなく、リバースエンジニアリングされたものです（[py2max](https://github.com/shakfu/py2max) の解析結果を `amxd.py` に取り込んでいます）。もし Live が読み込めなかったら、確実に動く手順があります。

1. Live で MIDIトラックに **Max Instrument**（空のデバイス）を置く
2. デバイスの編集ボタン（🔧）を押して Max エディタを開く
3. 中身を全選択して削除する
4. `GrainImage.maxpat` をテキストエディタで開き、**全文をコピー**する
5. Max のパッチャウィンドウで **ペースト**する（Max は JSON テキストのペーストをオブジェクトとして解釈します）
6. 保存する
